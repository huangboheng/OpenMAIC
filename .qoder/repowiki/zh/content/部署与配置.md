## 产品概述
OpenMAIC 是一个 AI 驱动的交互式课件（MAIC）生成与课堂管理平台，支持自然语言生成结构化课件、课堂实时互动（问答/讨论/测验）、课件编辑与回放。前端基于 Next.js + React，AI 编排层使用 LangGraph + Vercel AI SDK，核心业务模块位于 lib/ 目录，包含编排、生成、回放、智能体、课堂管理、编辑器与导出等能力。项目提供多种部署方式：Docker 容器化、Vercel 云平台以及传统服务器部署，并内置可选的隔离渲染服务用于 MP4 视频导出。

## 核心业务流程
- 用户通过 Web 界面发起课件生成或课堂任务，Next.js 应用处理请求并调用外部 AI 提供商（LLM/TTS/图像/视频等）。
- 当启用视频导出时，应用将渲染任务转发至独立的 render-service；该服务在隔离网络中运行 Chromium + FFmpeg，完成页面渲染与视频合成后返回结果。
- 应用根据环境变量与运行时健康检查动态启用/降级功能，例如未配置渲染服务时自动回退为 ZIP 下载路径。

## 关键约束与边界
- 容器与网络
  - 应用默认绑定 127.0.0.1:3000，仅本地可访问；渲染服务暴露 9000 端口并通过内部网络互通。
  - 渲染服务所在网络为 internal，禁止访问宿主与互联网；entrypoint 通过 iptables 进一步限制出站。
- 资源与安全
  - 渲染服务内存上限 4GB，并发与队列参数可调；需要 CAP_NET_ADMIN 以启用出站封锁。
  - 应用侧设置严格的安全响应头（CSP、X-Frame-Options、HSTS 等），生产环境启用 HSTS。
- 构建与平台
  - Next.js standalone 输出适用于自托管；Vercel 部署通过 vercel.json 指定函数超时与构建命令。
  - Node 版本要求 >= 20.9.0，pnpm 10.28；部分原生依赖需系统库（cairo/pango/jpeg/giflib/librsvg）。

## 部署指南

### Docker 容器化部署
- 镜像构建
  - 应用镜像：多阶段构建，基础镜像 node:22-alpine，安装 pnpm，编译依赖与构建产物，最终 runner 镜像仅包含运行时与静态资源。
  - 渲染服务镜像：基于 Debian bookworm-slim，安装 Chromium、FFmpeg、字体与 ca-certificates，使用 puppeteer 指向系统 Chromium。
- 服务编排
  - openmaic 服务：映射 127.0.0.1:3000，挂载 .env.local 与数据卷，设置 RENDER_SERVICE_URL 指向 render-service。
  - render-service 服务：仅随 profile video-export 启动，暴露 9000 端口，限制内存 4GB，添加 NET_ADMIN 能力。
- 启动命令
  - 普通启动：docker compose up --build
  - 启用视频导出：docker compose --profile video-export up --build

## SSL 证书与反向代理
**更新** 新增 Philochora + OpenMAIC 联合部署的 Nginx 配置管理，包含完整的 API 表面验证和安全加固，以及静态资源访问支持。

### Nginx 反向代理配置
- **Philochora + OpenMAIC 联合部署**
  - 配置文件位置：`deploy/nginx/philochora.conf`
  - 支持 HTTP 强制跳转到 HTTPS
  - TLS 证书管理（Let's Encrypt）
  - 安全响应头配置（X-Content-Type-Options、X-Frame-Options、HSTS、Permissions-Policy）
  - 大文件上传支持（client_max_body_size 200m）

- **API 表面契约管理**
  - 白名单模式：显式允许的路径（课堂播放、聊天、生成、健康检查等）
  - 黑名单模式：拒绝敏感路径（usage、provider、verify-*、comfyui-workflows、azure-voices）
  - 兜底规则：未匹配路径返回 403，防止未授权访问

- **静态资源访问支持**
  - **新增**：支持 favicon.ico、apple-icon.png、logos/ 等静态资源访问
  - 解决生产环境页面图标和加载指示器缺失问题
  - 与 proxy.ts 中的 PAGE_ENTRY_PATTERN 保持一致
  - 确保浏览器能够正常加载页面所需的静态资源

- **速率限制与性能优化**
  - 可选的速率限制区域配置（limit_req_zone）
  - SSE 流式响应支持（proxy_buffering off）
  - 静态资源缓存优化（assets/ 目录 365d immutable）
  - SPA 入口 HTML 不缓存（避免持有旧 bundle）

### 部署自动化脚本
- **Nginx 配置部署** (`scripts/deploy-nginx.sh`)
  - 支持 dry-run 模式预览差异
  - 自动备份远端配置（带时间戳）
  - nginx -t 语法校验失败自动回滚
  - 部署后穿透验证（server-providers 应不再返回 403）
  - 使用 reload（非 restart）避免中断现有连接

- **API 表面验证** (`scripts/check-api-surface.mjs`)
  - 静态扫描 app/api/** 所有路由
  - 验证每个路由都在 Nginx 配置中有显式落位
  - 阻断模式：违规时退出码 1，阻止推送
  - 对账模式：只输出清单，不阻断
  - 逃生口：SKIP_API_SURFACE_CHECK=1 跳过检查

- **数据同步脚本** (`scripts/deploy-sync.sh`)
  - 增量同步 data/classrooms/ 到 VPS
  - 支持 dry-run、checksum、verbose 模式
  - 自动备份被覆盖的文件
  - 远端数据量校验（JSON 和 MP3 文件数对比）

## 静态资源访问问题修复详解

### 问题背景
在生产环境部署中，发现页面图标（favicon.ico）、苹果图标（apple-icon.png）和供应商标志（logos/）无法正常加载，导致用户体验问题。

### 根本原因分析
- Nginx 配置中缺少静态资源的访问规则
- 与 proxy.ts 中的 PAGE_ENTRY_PATTERN 不一致
- 浏览器请求静态资源时被 Nginx 拦截返回 403

### 解决方案
在 Nginx 配置的白名单中添加静态资源访问规则：

```nginx
location ~* ^/openmaic/(api/(chat|classroom|classroom-media|generate-classroom|generate/(scene-content|scene-actions|scene-outlines-stream|agent-profiles|image|video|tts|voice)|quiz-grade|health|proxy-media|pbl|access-code|export-video|philochora|agent|extract-document|parse-pdf|transcription|web-search|persistence|auth/callback|public|server-providers)|classroom/|_next/|favicon\.ico$|apple-icon\.png$|logos/) {
    proxy_pass http://127.0.0.1:3010;
    # ... 其他代理配置
}
```

### 影响范围
- 解决了页面标题栏图标显示问题
- 恢复了移动端书签图标的正常显示
- 确保了供应商标志的正确加载
- 提升了整体用户体验

### 验证方法
1. 检查浏览器开发者工具的 Network 面板，确认静态资源请求返回 200 状态码
2. 验证页面标题栏图标是否正常显示
3. 测试移动端书签功能是否正常
4. 确认供应商标志在设置面板中正确显示
