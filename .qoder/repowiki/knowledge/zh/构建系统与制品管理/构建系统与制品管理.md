OpenMAIC 项目采用基于 pnpm workspace 的 monorepo 构建体系，以 Next.js 16 为核心应用框架，配合 Docker 多阶段镜像实现容器化部署。

## 构建系统架构

包管理器与 Monorepo: 使用 pnpm@10.28.0 作为包管理器，通过 pnpm-workspace.yaml 管理根应用和多个子包（packages/*、packages/@openmaic/*），docs 子应用独立排除。Node.js 版本锁定为 >=20.9.0，CI/CD 统一使用 Node 22。

核心构建流程:
- 开发环境：next dev 启动 Next.js 开发服务器
- 生产构建：next build 生成 standalone 输出模式，支持子路径部署（NEXT_PUBLIC_BASE_PATH）
- 依赖安装：postinstall 脚本自动构建所有 workspace 包（mathml2omml、pptxgenjs、@openmaic/dsl、storage、importer、renderer）

TypeScript 配置: 全局 tsconfig.json 启用严格模式，使用 bundler 模块解析策略，Next.js 插件集成，路径别名 @/* 指向根目录。

## 容器化部署

Docker 多阶段构建:
- base: Node 22 Alpine + pnpm 初始化
- deps: 安装原生依赖编译工具（sharp、canvas 等）
- builder: 完整构建 Next.js 应用
- runner: 最小化运行镜像，仅包含 .next/standalone 产物

安全配置: 通过 next.config.ts 设置 CSP、X-Frame-Options、HSTS 等安全头，支持 iframe 嵌套场景的 frame-ancestors 白名单。

## CI/CD 流水线

主 CI 流水线 (.github/workflows/ci.yml):
- Lint: ESLint + Prettier 检查
- Typecheck: TypeScript 类型检查
- i18n: 国际化键值对齐检查
- Unit Tests: Vitest 单元测试（根应用 + 各 @openmaic 包）
- E2E: Playwright 端到端测试

包发布流水线 (.github/workflows/publish-packages.yml):
- 触发条件：main 分支推送或 @openmaic/*@* 标签
- 构建顺序：dsl → renderer → importer（依赖拓扑排序）
- 预发布检查：打包内容审查、类型检查、单元测试
- 发布：带 provenance 签名的 npm 发布

文档构建: 独立的 packages/docs 子应用，使用 Next.js 静态导出，独立 lockfile 和工作区隔离。

## 关键约定与约束

- 依赖锁定: 使用 --frozen-lockfile 确保构建可重现性
- 原生依赖: sharp、@napi-rs/canvas 等原生模块在 Docker 中需要额外编译依赖
- 包版本管理: 第三方 fork 包（@earendil-works/*）固定精确版本 0.78.0
- 环境变量: 通过 NEXT_PUBLIC_BASE_PATH 支持子路径部署，ALLOWED_FRAME_ANCESTORS 控制 iframe 安全策略
- 构建产物: Next.js standalone 模式输出，便于容器化部署
