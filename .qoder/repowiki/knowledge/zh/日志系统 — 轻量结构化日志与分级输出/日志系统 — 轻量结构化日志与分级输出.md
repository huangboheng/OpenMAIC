## 1. 使用的系统/方案
仓库使用自实现的轻量级日志模块 `lib/logger.ts`，基于 Node.js `console` API 封装，提供四级日志（debug/info/warn/error）和两种输出格式（普通文本 / JSON）。未引入第三方日志框架（如 winston、pino、bunyan 等）。

## 2. 核心文件与包
- `lib/logger.ts`：唯一日志实现，导出 `createLogger(tag)` 工厂函数。
- 所有 API Route（`app/api/**/*.ts`）均通过 `import { createLogger } from '@/lib/logger'` 引入并创建带业务标签的 logger 实例。

## 3. 架构与约定
- **按模块打标签**：每个路由/模块调用 `createLogger('xxx')` 生成独立 logger，日志行统一包含 `[timestamp] [LEVEL] [tag] message` 结构。
- **分级过滤**：通过环境变量 `LOG_LEVEL`（默认 `info`）控制最低输出级别；低于该级别的日志直接丢弃。
- **格式切换**：通过环境变量 `LOG_FORMAT=json` 切换为 JSON 单行输出，便于被日志采集器解析。
- **错误对象处理**：传入 `Error` 实例时自动提取 `stack` 或 `message`，其他非字符串参数会 `JSON.stringify`。
- **输出目标**：仅输出到 `console`（debug/info/warn/error 分别映射到对应方法），无文件/远程 sink。

## 4. 开发者应遵循的规则
- 在需要记录日志的地方统一使用 `createLogger('模块名')` 获取 logger，不要直接调用 `console.*`。
- 优先使用语义化级别：调试用 `debug`，常规信息用 `info`，警告用 `warn`，异常用 `error`。
- 不要在 `debug` 级别记录敏感信息（token、密码等）。
- 如需结构化字段，建议将对象作为单个参数传入，由 logger 内部 `JSON.stringify` 序列化。
- 部署时通过 `LOG_LEVEL` 和 `LOG_FORMAT` 环境变量控制行为，无需修改代码。
- 前端组件中不建议直接使用此 logger（它依赖 `process.env`），仅在服务端 API Route 中使用。
