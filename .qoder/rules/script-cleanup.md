# 脚本停止与结束时机强制规则

所有脚本（调试、工具、数据、临时脚本）必须遵守以下硬性规定，违反即视为任务未完成：

## 强制要求

1. **任务结束必须停止**：任何启动的脚本进程，在任务完成后必须立即停止，禁止残留进程。每次任务结束前必须检查是否有残留的脚本进程（如 `Get-CimInstance Win32_Process` 检查 node/python 等），发现即清理。
2. **写脚本必须有结束时机**：编写脚本时必须设计明确的结束路径，三选一：
   - 任务完成自动退出（主流程结束即 `process.exit(0)` 或自然返回）
   - 超时自动退出（长时间任务必须设置超时兜底，如 `setTimeout` / 轮询上限）
   - 显式清理逻辑（`finally` 块中关闭连接、清理临时资源后退出）
3. **禁止无限挂起**：禁止编写只能手动终止（Ctrl+C / kill）的脚本；禁止无退出条件的循环或等待。
4. **前后台进程一视同仁**：后台运行的脚本（`is_background: true`）也必须由 agent 在任务结束前主动停止，不得依赖用户手动关闭。

## 任务结束检查清单

- [ ] 我启动的脚本进程是否已全部停止？
- [ ] 脚本是否都有结束时机设计？
- [ ] 无残留的 node/python/tsx 等脚本进程？
