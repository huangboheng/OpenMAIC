# 临时脚本（tmp-*）治理强制规则

临时脚本（scripts/ 下以 `tmp-` 开头的工具）只允许用于一次性探索与方案验证，禁止与正式方案长期重复并存。进程运行时的停止与结束时机要求另行遵守 `script-cleanup.md`。

## 何时允许创建 tmp-* 工具

只有**同时满足全部**以下条件才允许创建：

1. **一次性用途**：仅用于当前任务的探索、诊断或数据搬运，无跨会话复用价值
2. **正式方案尚未定型**：对应能力尚无正式脚本（scripts/ 下无非 `tmp-` 命名方案），或正式方案尚在调试中
3. **不进入长期依赖**：不会成为构建、部署、CI、其他脚本或文档的依赖项
4. **有明确退出计划**：创建时即确定最终去向（验证后删除，或合并进正式方案）

**禁止场景**：

- 已有正式方案时，禁止另写 `tmp-*` 重复实现同一能力（例：已有 `deploy-sync.sh` 时，禁止再写 `tmp-sync-*` 同步脚本）
- 禁止 `tmp-*` 脚本被其他脚本、配置文件或文档引用
- 禁止将正式方案改名为 `tmp-*`，或将 `tmp-*` 直接转正而不补齐正式能力

## 验证义务

1. **运行前**：先以 dry-run / 小样本 / 预览模式验证命令正确性，确认无破坏性操作（覆盖、删除、远端写入前必须预览）
2. **运行中**：输出关键结果（成功/失败、传输量、耗时），失败必须暴露原因
3. **运行后**：验证目标状态与预期一致（如远端文件数、内容校验），不能只凭退出码 0 判定成功
4. **结果留痕**：关键数据变更在任务汇报中说明，不依赖脚本本身长期存在

## 清理期限（三选一，取先到者）

1. **任务结束即清理**：任务完成后立即删除，或合并进正式方案后删除，禁止残留 `tmp-*` 文件
2. **正式方案定型即清理**：正式方案落地时，同一能力的 `tmp-*` 工具立即删除
3. **最长保留 7 天**：超过 7 天仍未定型的一律删除；确需保留的必须转正（补齐校验、参数化、配置外置）

清理动作：删除文件 + `git status` 确认无残留未跟踪的 `tmp-*` 文件。

## 与正式方案的边界

| 维度 | 正式方案（如 `deploy-sync.sh`） | 临时工具（`tmp-*`） |
| --- | --- | --- |
| 命名 | 明确动词命名，无 `tmp-` 前缀 | `tmp-` 前缀强制 |
| 能力 | 完整：校验、备份、dry-run、参数化 | 允许简化，仅限方案验证 |
| 配置 | 从 `.env*` / 环境变量读取 | 允许硬编码 |
| 生命周期 | 常驻，可跨会话复用 | 一次性，任务结束即清理 |
| git 跟踪 | 提交进版本库 | 禁止提交，保持未跟踪并删除 |

## 任务结束检查清单

- [ ] `git status` 无残留未跟踪的 `tmp-*` 文件？
- [ ] 新建的临时工具已删除或合并进正式方案？
- [ ] 与正式方案无重复功能并存？
